2 Modelo Conceptual (Diagrama ER)

Elaborado en Mermaid. Archivo fuente: modelo-conceptual.mmd en el repositorio.

Jerarquía Solapada y Total — Persona

Persona → Asistente / Ponente
Una persona puede ser asistente, ponente o ambos (solapada). Todo inscrito debe cumplir al menos uno (total). Estrategia: 3 tablas con FK compartida.

Jerarquía Disjunta y Total — Sesión

Sesion → Charla / Taller
Una sesión es exactamente de un tipo, nunca de ambos (disjunta y total). Estrategia: columna discriminadora tipo_sesion + tabla extendida con FK=PK.

Estrategias de Jerarquía

👥 Persona — Jerarquía Solapada (3 tablas)

Se usó Superclase + Subclases separadas. Cada fila en Asistente o Ponente tiene persona_id como PK y FK simultáneamente, reutilizando la identidad del supertipo. Permite registrar una persona en ambas tablas sin inconsistencias.

📋 Sesión — Jerarquía Disjunta (discriminadora)

La tabla Sesion contiene tipo_sesion VARCHAR CHECK IN ('Charla','Taller'). Las tablas Charla y Taller extienden con FK=PK, garantizando exactamente un tipo por fila.

4 Implementación SQL en PostgreSQL 18

Scripts ejecutados en orden: 01_schema.sql → 02_seed.sql → 03_queries.sql → 04_invalid_tests.sql desde una base de datos vacía, sin edición manual.

Fragmento representativo del Schema

CREATE TABLE Sesion (
  id          INT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  edicion_id  INT NOT NULL REFERENCES Edicion(id) ON DELETE CASCADE,
  sala_id     INT REFERENCES Sala(id) ON DELETE SET NULL,
  titulo      VARCHAR(200) NOT NULL,
  hora_inicio TIME NOT NULL,
  hora_fin    TIME NOT NULL,
  tipo_sesion VARCHAR(20) NOT NULL CHECK (tipo_sesion IN ('Charla', 'Taller')),
  CHECK (hora_fin > hora_inicio)
);
CREATE TABLE Prerrequisito (
  sesion_id        INT NOT NULL REFERENCES Sesion(id) ON DELETE CASCADE,
  prerrequisito_id INT NOT NULL REFERENCES Sesion(id) ON DELETE CASCADE,
  PRIMARY KEY (sesion_id, prerrequisito_id),
  CHECK (sesion_id != prerrequisito_id)  -- Evita autorrelacion
);

Consulta Multi-tabla (03_queries.sql)

SELECT p.nombre AS asistente, s.titulo AS sesion,
       e.nombre AS edicion, i.fecha_registro
FROM  Persona p
JOIN  Asistente  a  ON p.id         = a.persona_id
JOIN  Inscripcion i  ON a.persona_id = i.asistente_id
JOIN  Sesion      s  ON i.sesion_id  = s.id
JOIN  Edicion     e  ON s.edicion_id = e.id
ORDER BY e.fecha_inicio, s.hora_inicio;

6 Restricciones — 6 Operaciones Inválidas Rechazadas

Cada operación es rechazada por PostgreSQL por una restricción distinta definida en el schema.
1
Inscripción Duplicada — mismo asistente en la misma sesión
PRIMARY KEY
INSERT INTO Inscripcion (asistente_id, sesion_id) VALUES (1, 1);
ERROR: duplicate key value violates unique constraint "inscripcion_pkey"
DETAIL: Key (asistente_id, sesion_id)=(1, 1) already exists.
2
FK Inexistente — sala_id que no existe en la BD
FOREIGN KEY
INSERT INTO Sesion (..., sala_id, ...) VALUES (..., 999, ...);
ERROR: insert or update on table "sesion" violates foreign key constraint "sesion_sala_id_fkey"
DETAIL: Key (sala_id)=(999) is not present in table "sala".
3
Dominio Inválido — fecha_fin anterior a fecha_inicio
CHECK
INSERT INTO Edicion (nombre, anio, fecha_inicio, fecha_fin, estado)
VALUES ('Bad Edition', 2026, '2026-10-12', '2026-10-10', 'Activa');
ERROR: new row for relation "edicion" violates check constraint "edicion_check"
DETAIL: Failing row contains (Bad Edition, 2026, 2026-10-12, 2026-10-10, Activa).
4
Dato Obligatorio Ausente — correo NULL en Persona
NOT NULL
INSERT INTO Persona (nombre, correo, pais) VALUES ('Sin Correo', NULL, 'Mexico');
ERROR: null value in column "correo" of relation "persona" violates not-null constraint
DETAIL: Failing row contains (7, Sin Correo, null, Mexico).
5
Autorrelación Inválida — sesión prerrequisito de sí misma
CHECK RECURSIVO
INSERT INTO Prerrequisito (sesion_id, prerrequisito_id) VALUES (1, 1);
ERROR: new row for relation "prerrequisito" violates check constraint "prerrequisito_check"
DETAIL: Failing row contains (1, 1).
6
Segundo acuerdo — misma empresa y edición (violación UNIQUE)
UNIQUE
INSERT INTO AcuerdoPatrocinio (empresa_id, edicion_id, categoria, monto, fecha_confirmacion)
VALUES (1, 1, 'Plata', 2000.00, '2026-05-01');
ERROR: duplicate key value violates unique constraint "acuerdopatrocinio_empresa_id_edicion_id_key"
DETAIL: Key (empresa_id, edicion_id)=(1, 1) already exists.
